# 01 · 工具链实测笔记（极语言 / D:\SEC）

本文所有结论都来自本机实测（2026-09，Windows 10 + PowerShell 5.1）。标注「实测」的都有可复现命令与观察结果；标注「未实测」的仅为文档描述。

## 1. 目录与文件

| 路径 | 作用 |
|---|---|
| `D:\SEC\Sec.exe` | 官方集成 IDE（自带编辑 + 编译）。GUI 程序，标题 `简易编程`/官方界面 |
| `D:\SEC\Sc.exe` | 独立编译器（VB6，窗口类 `ThunderRT6Main`，标题 `简易编程`）；给定源码路径时会**自动编译** |

| `D:\SEC\deepseek-sec\` | 本次工作区：`tools\`（sec.ps1/shot.ps1）、`examples\`、`notes\`、`shots\`、`docs\`（htm→UTF-8 纯文本） |

## 2. 编译方式（实测）

```powershell
# 命令行编译：给源码完整路径即可（文档说不需要引号）
Start-Process D:\SEC\Sc.exe -ArgumentList 'D:\path\demo.txt' -PassThru
```

实测行为：

1. `Sc.exe` 打开源码后**立刻自动编译**（无需点按钮）。
2. 编译完成后弹出**模态结果对话框**：窗口类 `ThunderRT6FormDC`，标题栏是**产物路径**（如 `D:\path\demo.com`，失败时也可能为空），内含一个 `ThunderRT6TextBox` 显示编译器消息：
   - 成功：`编译完毕. 用时:0.016 秒. 文件大小:2048 字节.`
   - 失败：`-> 未定义的名称:xxx [demo.txt :第N行]`、`-> 语法有误`、`-> 符号 写文字 不存在.`，或 `-> 内部错误 -> Invalid procedure call or argument [:第0行]`
   - **行号规则**：报错行号 = 源码行号 − **配置行数**（配置行不计入）。例：源码第 37 行报 `第35行`（2 条配置行）；源码第 25 行报 `第23行`。定位时把行号加回配置行数。
3. 产物写到**源码同目录**：
   - 控制台（`程序类型=2`）默认 `.com`，但它是**真正的 32 位 PE**（`MZ` + `e_lfanew=0x40` + `PE\0\0`，machine `0x14C`，optional magic `0x10B`），可直接运行。
   - GUI（默认 `程序类型=0`）为 `.exe`。
   - `定义 后缀=exe;` 可改扩展名（实测 `u2.txt` → `u2.exe`）。
4. 产物文件**有时在 Sc.exe 退出瞬间才落盘**，因此编译后要轮询等待文件出现（`sec.ps1` 已处理）。
5. 编译完成后 `Sc.exe` 会**继续停在编辑器窗口**，必须显式结束进程，否则残留。

## 3. 源码格式要求（实测，最重要）

- **编码必须是 GBK/ANSI**：UTF-8（无 BOM）→ 报 `未定义的名称:绋嬪簭绫诲瀷`（`程序类型` 被按 GBK 解码成乱码）；带 BOM → 报 `未定义的名称:锘跨`。
- **换行必须是 CRLF**：LF-only 源码 → `-> 内部错误 -> Invalid procedure call or argument [:第0行]`（同样的代码换成 CRLF 立即 `BUILD_OK`，实测 `core-cheatsheet.txt` 从 FAIL 变 OK）。
- 扩展名：`.sec` 是 IDE 的**二进制单文件源码**（不要手写）；纯文本源码用 `.txt` / `.SEC` / `.极` 均可。
- `sec.ps1` 会自动把 UTF-8（含 BOM）与 LF 归一化成 GBK + CRLF，因此用任意编辑器写完后直接编译即可。

## 4. 配置行（位置敏感，实测）

```
程序类型=2          ← 必须第 1 行
模块文件=CMD.inc    ← 必须第 2 行（若需要）
定义 位数=32;       ← 第 3 行起，可多条
定义 后缀=exe;
```

- `程序类型`（petype，文档）：`0` 初级 Windows/GUI（默认）、`1` 扩展 DLL、`2` 命令控制台、`3` 函数类库、`4` 基础应用、`5` 网络服务、`6` 单片机、`7` 无系统环境；再加 `8/16/32/64` 表示位宽、`128` 宽字符环境。
- 实测反例：把 `定义 位数=32;` 放第 1 行 → `未定义的名称:程序类型 [第2行]`；把 `定义 后缀=exe;` 插在 `模块文件` 之前 → `未定义的名称:模块文件`；写两个 `模块文件=` 行 → `未定义的名称:模块文件`；同一行写 `程序类型=2 模块文件=CMD.inc` → `程序入口 语法有误`。
- `定义 位数=32/64` 实测**不改变**控制台产物扩展名（仍 `.com`），但会改变产物架构：默认 32 位 → PE `machine=0x14C`；`定义 位数=64;` → PE `machine=0x8664`、optional magic `0x20B`（64 位，能在本机正常运行）。
- ★ `定义 位数=64;` 还是**文本类卡死的解药**：局部 `文本 x[n]="字面量"`、结构体含 `文本` 成员、子类无参方法在默认 32 位下会卡死/崩溃，加上这一行就正常（实测 w64a/w64b/w64c → `abc` / `生命=100 名字=赵子龙` / `说话被调用`）。
- `模块文件=CMD.inc` 提供 C 运行库符号（`写文字/写格式/内存复制/命令行/开文件…`）；不加则报 `符号 写文字 不存在.`。
- ★ **模块列表可以用逗号分隔**（主 agent 实测）：`模块文件=CMD.inc,dll.inc` —— 编译器会依次加载两个模块。`dll.inc` 头部是 `引入 "lib\user32.lib","lib\kernel32.lib","lib\shell32.lib","lib\ws2_32.lib","lib\msvcrt.lib";`，因此这一行能**解锁 Win32 与 Winsock 全套中文函数**（实测：`网络启动($202,数据)=0`、`分配(2,1,6)=260`、`连网` 到本机开放端口返回 `0`、关闭端口返回 `-1`）。
  - 若用冒号或空格分隔（`CMD.inc:网络通讯.sc` / `CMD.inc 网络通讯.sc`）→ `内部错误 -> Subscript out of range`。
  - `模块文件=CMD.inc,GUI.inc` 会因 GUI.inc 需要用户提供 `加载窗体` 而报 `未定义的名称:加载窗体 [GUI.inc:第11行]`——控制台程序别混入 GUI 模块。
- 文档提到 `模块文件=function:export` 是给 `函数`/`导出` 关键字做「参数预声明」的工程配置（放在最前面、不能有多余符号）——本机未验证出可用写法的组合，因此**辅助函数统一用 `程序`**。

## 5. `.sec` 二进制源码格式（部分逆向，实测）

以 `D:\SEC\code\控制台彩字.sec`（422 字节）为例，头部字节：

```
01 42 | 07 00 "CMD.inc" | 0A 00 "控制台.bac" | 4B 01 <331 字节 GBK 源码> | 66 字节尾部元数据
```

- 第 0 字节：控制台程序为 `01`，GUI 程序为 `02`（`遍历.sec`/`计算器.sec` 均为 `02`）。
- 第 1 字节：即 petype——`0x42`=66=2+64（64 位控制台）、`0x22`=34=2+32（32 位控制台）、`0x20`=32（32 位 GUI）。
- 之后是若干 `[u16 长度][名称]` 模块项（`CMD.inc`、`GUI.inc` 这类 include，以及 `控制台.bac`、`窗体.frm` 这类 IDE 设计器文件）。
- 然后是 `[u16 源码长度][GBK 源码]`，最后是尾部元数据（`z5x.cn`、`Free`、`1.00`、工程名、`工程名.exe`、图标等）。
- **读官方示例**（源码区就是普通 GBK 文本）：
  ```powershell
  [Text.Encoding]::GetEncoding('GB18030').GetString([IO.File]::ReadAllBytes('D:\SEC\code\计算器.sec'))
  ```

## 6. 编译运行工具 `scripts/sec.ps1`

```
powershell -File sec.ps1 -Src <源码绝对路径> [-Run] [-RunSeconds 6] [-WaitSec 15]
```

- 串行安全：不抢全局资源，可多个进程并发调用（实测 3 个并发编译全部 `BUILD_OK`）。
- 自动：归一化源码编码/换行 → 清理旧产物 → 启动 Sc.exe → 轮询结果对话框 → 读取编译器消息 → 关闭对话框并结束 Sc.exe → 等待产物落盘 →（可选）运行并抓取 stdout。
- 输出：`BUILD_OK`/`BUILD_FAIL`、`--- compiler messages ---`、`DIALOG_TITLE`、`ARTIFACT`、`--- program output ---`（含 `[exit=N]`）。
- 判定规则：产物存在且消息中不含 `内部错误/未定义的名称/不存在/语法有误` 才 `BUILD_OK`。
- 运行抓取：stdout/stderr 按 GBK 解码；超时（`-RunSeconds`）会杀进程**并自动重试一次**——因为实测「刚编译完的程序首次启动偶发假死」，重试即正常。
- 已知局限：卡死的程序（如踩了 `文本=字面量` 的坑）不会产出 stdout，但它的**控制台窗口里能看到真实输出**，用 `shot.ps1` 截图定位。

## 7. 窗口截图工具 `scripts/shot.ps1`

```
powershell -File shot.ps1 -Title <标题子串> -Out <png路径>     # 推荐：对 .com 产物也有效
powershell -File shot.ps1 -Proc <exe名> -Out <png路径>        # .exe 可用；.com 的进程名是 "demo.com"
```

用 `PrintWindow` 抓窗口位图存 PNG，可用 `read_image` 工具查看。用完记得 `Stop-Process` 掉自己启动的进程。

## 8. 排错速查

| 编译器消息 | 首查 |
|---|---|
| `未定义的名称:程序类型/模块文件` | 配置行顺序/数量/是否同一行 |
| `未定义的名称:绋嬪簭绫诲瀷` 之类乱码 | 源码不是 GBK |
| `未定义的名称:<某关键字>` | 该关键字本版不存在（如 `小程序`、`程序段`、`改文本`），或缺少 `模块文件=CMD.inc` |
| `符号 XXX 不存在.` | 缺模块（C 运行库函数需 `CMD.inc`） |
| `语法有误` | 上一行缺分隔符；`判断` 多写了 `结束`；运算符写错（如 `%` 取模） |
| `内部错误 -> Invalid procedure call or argument [:第0行]` | LF 换行；`a%b`；`函数` 定义辅助函数；语句组合过复杂 → 二分拆小定位 |
