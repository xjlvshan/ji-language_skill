## 0. 三条最容易踩的致命前提

| 前提 | 现象 | 实测证据 |
|---|---|---|
| **源码必须 CRLF 换行** | 只写 LF 时 GUI 程序编译直接报 `-> 内部错误 -> Invalid procedure call or argument [:第0行]`（控制台程序不一定触发，但 GUI 必炸） | `gui-raw5.txt`（CRLF）→ BUILD_OK；`gui-raw6.txt`（同内容只改 LF）→ BUILD_FAIL「Invalid procedure call or argument [:第0行]」 |
| **GUI 入口必须自己写 `程序 加载窗体`** | GUI.inc 第 11 行写死了 `加载窗体` 调用，但它自己不定义它 | GUI.inc 只有 `程序 程序入口`/`程序 读取消息`；不定义加载窗体时编译报 `-> 未定义的名称:加载窗体 [GUI.inc:第11行] -> 内部错误 -> [gui-raw4.txt :第1行]` |
| **不要重复声明 GUI.inc 已内置的名字** | 编译能过，但每次都刷 4 条警告 | `gui-1.txt` 未清理时输出「已存在常量名:实例 / 已存在变量名:界面 / 已存在变量名:消息 / 已存在变量名:桌面」；清理后（`gui-1.txt` 最终版）编译消息只剩「编译完毕」 |

补充：`工具 sec.ps1` 的全局互斥量若被别的 agent 弄成 abandoned，会抛 `The wait completed due to an abandoned mutex.` —— **重跑一次即可**（实测第二次成功）。

## 1. GUI 程序骨架（GUI.inc 逐行解读）

`D:\SEC\inc\GUI.inc` 全文只有 12 行有效代码（GBK，550 字节）：

```
引入 "lib\user32.lib","lib\kernel32.lib","lib\gdi32.lib","lib\shell32.lib","lib\comdlg32.lib","lib\advapi32.lib","lib\comctl32.lib","lib\gdiplus.lib","lib\ole32.lib","lib\ws2_32.lib","lib\msvcrt.lib";

窗口类 界面(风格=$8B,背景=6)消息类 消息;
矩形类 桌面;常量 实例=$400000,程序.名称="SecClass";
程序 程序入口
列举 界面{.消息=@窗体消息
.名称="SecClass"
.图标 = 载入图标(实例,1)
.光标=载入光标(0,32512)}
注册窗类(界面)窗口边界(桌面窗口, 桌面)
加载窗体
结束
程序 读取消息
循环(获取消息(消息,0,0,0)){翻译消息(消息)分派消息(消息)}
结束
```

要点：

- `窗口类 界面(风格=$8B,背景=6)` —— `$8B = CS_VREDRAW(1)+CS_HREDRAW(2)+CS_DBLCLKS(8)+CS_OWNDC($80)`；`背景=6` 是系统画刷 `COLOR_WINDOW+1`。
- `消息类 消息;` —— WM_MSG 结构体全局变量，`矩形类 桌面;` —— RECT 全局变量。
- `常量 实例=$400000,程序.名称="SecClass";` —— **这两个名字 GUI.inc 已经定义**，用户代码不要再写 `常量 实例=...`（会出「已存在常量名」）。
- `程序 程序入口` 里做：填 `界面.消息=@窗体消息`（消息过程地址）→ `注册窗类(界面)`（RegisterClass）→ `窗口边界(桌面窗口, 桌面)`（GetClientRect 取桌面尺寸）→ 调用**用户必须自己定义的 `程序 加载窗体`**。
- `程序 读取消息` 就是消息泵：`循环(获取消息(消息,0,0,0)){翻译消息(消息)分派消息(消息)}`。
- 消息过程签名固定为 `程序 窗体消息(窗口,消息,参数,数据)`，内部 `否则{处理窗口(窗口,消息,参数,数据)}` 把消息交回默认处理。

### 最小可运行 GUI 模板（已实测 BUILD_OK + 出窗口）

```
模块文件=GUI.inc
整数 窗体;
程序 加载窗体
	窗体=创建窗口($100,程序.名称,"标题",$10C80000,100,100,400,200,0,0,0,0);
	读取消息
结束
程序 窗体消息(窗口,消息,参数,数据)
	判断(消息)
	为 窗口关闭{停止(0)}
	否则{处理窗口(窗口,消息,参数,数据)}
结束
```

- 实测：`gui-raw5.txt` → BUILD_OK，2560 字节产物；`Start-Process gui-raw5.exe` 后窗口类名 `SecClass`、标题 `测试`、rect=100,100,400,300（`cap.ps1` 输出）。
- **不需要写 `程序 程序入口`！** GUI.inc 已经提供，用户只写 `程序 加载窗体` 即可（实测 `gui-raw5.txt` 就没写程序入口，照样跑）。
- 若确实要写 `程序 程序入口`（官方 .sec 都写了），必须完整照抄 GUI.inc 里那 7 行，并把 `加载窗体` 换成自己的过程名 —— `gui-1.txt`/`gui-2.txt`/`gui-4.txt` 采用这种方式，全部 BUILD_OK。
- `停止(0)` = 结束本程序（退出消息泵）。

## 2. `创建窗口(...)` —— 12 个参数的确切含义

语法：

```
窗口句柄 = 创建窗口(类型, 类名, 标题, 风格, 左, 上, 宽, 高, 父窗口, 菜单/控件ID, 实例, 参数)
```

各参数（结合 `计算器.sec`、`遍历.sec`、`画图.sec` 与实测句柄对照）：

| # | 名称 | 实测含义 |
|---|---|---|
| 1 | 类型 | 窗口类型/附加标志。`$100`=普通顶层窗口或带边框的控件（**最常用**）；`$200`=带 `WS_EX_CLIENTEDGE`（凹陷边框）的控件（官方对 listbox/Edit 多用 `$200`）；`$0`=无附加（按钮/静态框常用）；`$10` 也见用于顶层窗口（`拖曳文件.sec`） |
| 2 | 类名 | 窗口类名。顶层窗口用 `程序.名称`（= `"SecClass"`，GUI.inc 注册的类）；控件用系统类名 `"Button"`/`"Edit"`/`"Static"`/`"listbox"`/`"combobox"`/`"ScrollBar"`/`"msctls_progress32"`/`"msctls_trackbar32"` |
| 3 | 标题 | 窗口标题 / 控件文字（Edit 的初始内容也在这里） |
| 4 | 风格 | 窗口风格位（见下一节）。控件的子窗口风格必须含 `$40000000`(WS_CHILD)+`$10000000`(WS_VISIBLE) |
| 5–8 | 左、上、宽、高 | 相对父窗口客户区的像素坐标/尺寸；顶层窗口是屏幕坐标 |
| 9 | 父窗口 | 顶层窗口写 `0`；控件写真窗体句柄 |
| 10 | 菜单/控件ID | 顶层窗口这里是**菜单句柄**（`画图.sec`：`...,0,菜单,0,0`）；**控件这里就是控件 ID**（决定了 `单击左键` 消息 `参数` 的低 16 位） |
| 11 | 实例 | 官方示例对控件写 `3`/`4`/`2`/`9`/`10`/`22`…；实测**写成什么都能创建成功**（`gui-1.txt` 用 3，控件正常）。此位看起来是「控件类别/资源提示」，功能上未观察到影响 → **未验证其确切语义** |
| 12 | 参数 | 官方示例恒写 `0` |

实测证据：
- `winprobe.ps1 -Proc gui-1 -Dump` 输出
  `cls=Static id=1` / `cls=Button id=2` / `cls=Edit id=3` —— 第 10 个参数（1/2/3）就是 `GetDlgCtrlID` 读到的控件 ID，一一对应。
- `遍历.sec`：`列表=创建窗口($200,"listbox","列表框",$50210081,0,0,230,290,窗体,1,9,0);`

### 窗口类型 `$100` / `$200` / `$0` 的差别

- `$100` = `WS_EX_WINDOWEDGE`? 实测表现更像「带边框/标题的顶层窗口」标识；GUI.inc 的顶层窗口都用 `$100`（`计算器.sec`、`遍历.sec` 等）。
- `$200` = `WS_EX_CLIENTEDGE`（凹陷 3D 边框）—— 官方给 `listbox`/`Edit` 用它，视觉上有下沉边框（`gui-2.png` 里编辑框/列表框确有下沉边框，而 `gui-1.txt` 里 Edit 用 `$200` 也一样）。
- `$0` = 无扩展风格 —— 按钮/静态框用它。
- **未验证**：这三个值是否真被当成 `dwExStyle` 直接透传（编译产物太小、无法直接反汇编确认）。

## 4. 事件模型（消息分派）

### 4.1 `窗体消息(窗口,消息,参数,数据)` + 判断链

```
程序 窗体消息(窗口,消息,参数,数据)
	判断(消息)
	为 窗口关闭{停止(0)}
	为 单击左键{左键点击(参数)}
	为 定时事件{定时器消息(参数)}
	否则{处理窗口(窗口,消息,参数,数据)}
结束
```

- 顺序：**先 `判断(消息)` 处理自己关心的，最后 `否则{处理窗口(...)}` 兜底**。官方 `计算器.sec` 甚至把 `处理窗口` 写在判断之前，也能跑，但推荐兜底写法。
- 消息常量是中文名，值见手册（`窗口关闭`=`WM_CLOSE $10`、`单击左键`=`WM_COMMAND $111`、`鼠标移动`=`WM_MOUSEMOVE $200`、`按下左键`=`$201`、`释放左键`=`$202`、`键盘按下`=`$100`、`定时事件`=`WM_TIMER $113`、`绘制按钮`=`$135`、`绘制静态`=`$138`、`拖放文件`=`WM_DROPFILES $233`、`滚轮转动`=`$20A`、`水平滚动`=`$114`、`窗口缩放`=`$5`）。

### 4.2 `单击左键` 的 `参数` 编码 —— 本次最重要的实测

**`参数` = `通知码 << 16 | 控件编号`**（标准 WM_COMMAND 的 wParam）。

实测（`gui-1.txt` 最终版，点「测窗口消息」按钮后读回静态框文字）：

```
winprobe.ps1 -Proc gui-1 -Click 2
winprobe.ps1 -Proc gui-1 -Dump
  -> cls=Static id=1 text='控件编号=2 通知码=0 参数=2'
```

- 按钮单击（BN_CLICKED=0）：`参数=2`，低 16 位=2=控件 ID，高 16 位=0=通知码。
- 编辑框获得焦点（EN_SETFOCUS=0x100）：早期探测版 `gui-2` 在启动瞬间就把标题写成 `param=50331650 lo=2 hi=768` —— `50331650 = 0x03000200`，低 16 位=2（控件 ID），高 16 位=768=`0x300`。**注意：这里 hi 是 0x300 而不是 0x100**，与手册 EN_SETFOCKS 表（0x100）不一致 → **疑点，未复测**。
- 通知码常量（手册 4560 行按钮段 / 4384 行编辑框段 / 4712 行组合框段 / 5026 行列表框段）：
  - 按钮 `BN_CLICKED=0`、`BN_PAINT=1`、`BN_HILITE=2`、`BN_UNHILITE=3`、`BN_DISABLE=4`、`BN_DOUBLECLICKED=5`、`BN_SETFOCUS=6`、`BN_KILLFOCUS=7`
  - 编辑框 `EN_SETFOCUS=0x100`、`EN_KILLFOCUS=0x200`、`EN_CHANGE=0x300`、`EN_UPDATE=0x400`、`EN_ERRSPACE=0x500`、`EN_MAXTEXT=0x501`、`EN_HSCROLL=0x601`、`EN_VSCROLL=0x602`
  - 组合框 `CBN_SELCHANGE=1` … `CBN_SELENDCANCEL=10`
  - 列表框 `LBN_SELCHANGE=1`、`LBN_DBLCLK=2`、`LBN_SELCANCEL=3`、`LBN_SETFOCUS=4`、`LBN_KILLFOCUS=5`、`LBN_ERRSPACE=-2`
- **坑：`判断(参数 & $FFFF)` 编译报「语法有误 + 内部错误」**。实测 `probe2.txt`/`probe8.txt`（不写空格 `参数&$FFFF`）以及 `gui-1.txt` 早期版（写空格 `参数 & $FFFF` 但直接放判断里）都失败；必须**先赋值给变量再判断**：
  ```
  整数 编号=参数 & 65535,通知=参数 >> 16;
  判断(编号) 为 2{...}
  ```
  实测 `probe3.txt`（赋值形式）BUILD_OK，`gui-1.txt` 最终版 BUILD_OK。（另：不写空格 `参数&$FFFF` 会被切成 `参数` `&` `$FFFF` 之外的记号，报 `未定义的名称:FFFF`。）
- 窗体客户区单击时 `参数=0`、`数据` 是鼠标坐标（未单独复测，手册如此）。

### 4.3 控件事件（`控件事件` = WM_NOTIFY）

```
判断(消息) 为 控件事件 公共事件(数据)
程序 公共事件(数据)
	整数 窗口=数据&,参数=.&4,事件=.&8
	处理窗口(窗口,控件事件,参数,数据)
结束
```
`数据` 指向 `通知类(NMHDR)`：偏移 0=窗口，4=控件 ID，8=事件（负数，如 `-2`=控件单击左键 `NM_CLICK`，见手册 3667 行起）。用 `数据&` / `.&4` / `.&8` 取。**未实测**（本次未搭 表格/树表/选卡等公用控件做验证）。

### 4.4 绘制控件时改字体 / 颜色

- 手册 3591 行：`判断(消息) 为 绘制按钮{发送消息(数据,指定字体,字体,0)}` —— `数据` 是控件句柄，`发送消息(hwnd, WM_SETFONT, hFont, 0)`。

### 用 `判断` 链改状态文本的安全写法（实测可用）

```
程序 左键点击(参数)
	整数 编号=参数 & 65535,通知=参数 >> 16;
	文本 内容[160];
	判断(编号)
	为 2{格式化(内容,"控件编号=%d 通知码=%d 参数=%d",编号,通知,参数);改控件字(窗体,1,内容)}
	否则{...}
结束
```

- `文本 内容[160];` 在**函数内**声明后由 `格式化` 填充，再交给 `改控件字` —— 实测可行（`gui-1.txt`、`probe27.txt`）。

### 定时器（`D:\SEC\inc\定时器.sc`）

## 11. 坑清单（按重要性）

1. **GUI 源码必须 CRLF**（LF 直接内部错误）—— 与 AGENT-BRIEF 只提「GBK」不同，这是 GUI 的额外硬条件。
2. **GUI.inc 不含 `加载窗体`**，用户必须自己 `程序 加载窗体`。
3. **`实例/界面/消息/桌面` 已被 GUI.inc 定义**，别重复声明。
4. **判断条件里不能直接用 `&`/`>>` 表达式**，必须先赋给变量。
5. **`设置定时器` 不存在**，正确符号是 `设置定时(窗口,编号,毫秒,@回调)`；`定时器.sc` 里的 `定时器` 过程只是宏包装。
6. **改 Edit 的文字三条路全废**（改控件字 / 改窗口字 / 发送消息-设置文本），只能改 Static/Button。
7. **`改控件字(...,"字面量"+整数)` 拼接无效**，用 `格式化` 到文本缓冲。
8. **`文本 变量[32]="字面量";` 会死循环**（编译器 bug），用 `内存复制` 或直接字面量。
9. **`圆角矩形` 不带「画」字**。
10. **自绘（取设备 + 画…）会盖住子控件**，别把控件放在自绘区域。
11. **标准滚动条要父窗口带 WS_HSCROLL/WS_VSCROLL** 才能收到滚动消息。
12. 定时器回调里发 `进度步进` 疑似导致进程崩溃（改 `进度取值/进度位置` 后正常）。
13. `工具 sec.ps1` 的互斥量可能被上一次崩溃弄成 abandoned，重跑一次即可。
14. `tools\shot.ps1` 本会话确认可用（父 agent 修过变量冲突）；输出格式 `saved <path> (WxH) hwnd=... title='...'`。**自建 `tools\cap.ps1` 在部分窗口上 PrintWindow 抓不到子控件**，以 `shot.ps1` 为准。
