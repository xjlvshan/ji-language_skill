## 1. 一个可用的完整 GUI 应用骨架

```ji
模块文件=GUI.inc
定义 后缀=exe;              // 必须写在 模块文件 之后

结构 启动结构{整数 大小,预留,桌面,标题,左,顶,宽,高,列,行,属性,标志,显示,备用,输入,输出,错误;}
结构 过程结构{整数 进程,线程,进程号,线程号;}

整数 窗体;
文本 期望路径[512];

程序 加载窗体                 // 入口（GUI.inc 已提供 程序入口/读取消息）
	矩形类 客户区;             // ★ 局部声明必须全部在最前面
	整数 窗宽,窗高,左,上;
	客户区.左=0;客户区.顶=0;客户区.宽=880;客户区.高=800;
	调整窗口(客户区,$10C80000,0);         // 让「客户区」正好 880x800
	窗宽=客户区.宽-客户区.左;
	窗高=客户区.高-客户区.顶;
	左=(桌面.宽-窗宽)>>1;
	上=(桌面.高-窗高)>>1;
	如果(上<0){上=0}
	窗体=创建窗口($100,程序.名称,"窗口标题",$10C80000,左,上,窗宽,窗高,0,0,0,0);
	// ... 建控件 ...
	读取消息
结束

程序 窗体消息(窗口,消息,参数,数据)
	判断(消息)
	为 窗口关闭{收尾;停止(0)}
	为 单击左键{命令事件(参数)}
	为 定时事件{定时到(参数)}
	否则{处理窗口(窗口,消息,参数,数据)}
结束
```

- `调整窗口(矩形,样式,菜单)` = `AdjustWindowRect`：先用客户区尺寸换算出**窗口**尺寸，
  再 `创建窗口`，否则底部控件会被标题栏挤掉。
- `桌面.宽 / 桌面.高` 由 GUI.inc 的 `窗口边界` 填充，可直接用来居中。
- **控件 ID 用 `常量` 统一编号**（`常量 编号_按钮=3,...`），`创建窗口` 第 10 参传它。

## 2. ★ 控件内容读写：官方 `~` 运算符（强烈推荐）

`D:\SEC\sec.htm` 第 558 行：

```
~  字  内容~文本框1，读写控件内容。左边为文本变量读取右边控件；
      左边为控件对象是把右边内容写入控件
```

实测（`examples/31-gui-control-io.txt` + 截图）：

```ji
文本 缓冲[1024];
缓冲 ~ 编辑;            // 读：编辑框内容 -> 缓冲
标签 ~ "新文字";        // 写：把字面量写进静态标签
编辑 ~ 缓冲;            // 写：把缓冲写进编辑框
```

要点：

- **读**：`文本变量 ~ 控件句柄;` —— 左边必须是 `文本` 变量（全局/局部均可）。
- **写**：`控件句柄 ~ 内容;` —— 右边可以是 `文本` 变量或字面量。
- 对 **多行只读 Edit**，`改控件字(窗体,ID,文本)` 在本项目里会把程序搞崩，
  换成 `控件_输出框 ~ 载荷;` 后完全正常。**读写控件内容优先用 `~`。**
- `改控件字(窗体,ID,文本)` 对 Static / Button **正常**（状态栏就是这么刷的），
  4 参形式 `取控件字(窗体,ID,缓冲,大小)` 也可用，但 `~` 更省事、覆盖面更广。

## 3. 列表视图 `SysListView32` 完全指南

### 3.1 建控件

```ji
列表=创建窗口($200,"SysListView32","",$50810001,16,184,680,300,窗体,5,0,0);
```

`$50810001` = `WS_CHILD|WS_VISIBLE|WS_BORDER|WS_TABSTOP|LVS_REPORT`。
（`$50810000` 不带 LVS_REPORT 就是图标模式，表头不会出现。）

### 3.2 ★ LVM 消息常量（实测，用错会直接崩）

| 用途 | 常量 | wParam | lParam |
|---|---|---|---|
| 插入列 | `$101B` | 列序号 | `@列结构` |
| 插入项（行） | `$1007` | 0 | `@项结构` |
| 写子项文字 | `$102E` | 行号 | `@项结构` |
| 取子项文字 | `$102D` | 行号 | `@项结构`（`.文字` 指向接收缓冲） |
| 删除指定行 | `$1008` | 行号 | 0 |
| 清空全部 | `$1009` | 0 | 0 |
| 取行数 | `$1004` | 0 | 0 |
| 取下一个选中行 | `$100C` | 起始行（-1 表示从头） | `2`（LVNI_SELECTED） |
| 设置/取行高、间距 | `$1036` | 0 | 样式 |

> 注意：`$100D` 是 `LVM_FINDITEM`，`$101D` 是 `LVM_GETCOLUMNWIDTH`，
> **不是**插入项/插入列。写反了程序会静默崩（0xC0000409）。

### 3.3 结构体（字段顺序必须与 Win32 一致）

```ji
结构 列结构{整数 掩码,格式,宽,文字,字长,子项,图,序;}                    // LVCOLUMNA
结构 项结构{整数 掩码,项,子项,状态,状态掩码,文字,字长,图,附加;}          // LVITEMA 前 9 个字段
```

### 3.4 四列 + 加行（实测通过，见示例 31 截图）

```ji
程序 列(序号,宽度,标题)
	列结构 列;
	列.掩码=3;                     // LVCF_FMT|LVCF_WIDTH|LVCF_TEXT
	列.格式=0;
	列.宽=宽度;
	列.文字=标题;
	列.字长=文字长度(标题);
	列.子项=序号;
	列.图=0;
	列.序=序号;
	发送消息(列表,$101B,序号,@列);
结束

整数 行数=0;

程序 加行(内容)
	项结构 项;
	行数=行数+1;
	项.掩码=1;                     // LVIF_TEXT
	项.项=行数-1;
	项.子项=0;
	项.文字=内容;
	项.字长=文字长度(内容);
	发送消息(列表,$1007,0,@项);    // 插入行
	项.子项=1;项.文字="第二列";项.字长=6;
	发送消息(列表,$102E,行数-1,@项);

```

### 3.5 取选中行 / 取单元格文字

```ji
程序 选中行数
	整数 计数,行;
	计数=0; 行=-1;
	循环
	{
		行=发送消息(列表,$100C,行,2);

	}

结束

程序 取单元格(行,列,出口,出口大小)

	项.项=行;
	项.子项=列;
	项.文字=出口;         // 目标缓冲
	项.字长=出口大小;

	发送消息(列表,$102D,行,@项);
	返回(文字长度(出口))
结束
```

## 5. 剪贴板

```ji
程序 复制到剪贴板(内容)
	整数 长,内存,址;
	长=文字长度(内容)+1;
	内存=全局分配($42,长);          // GMEM_MOVEABLE|GMEM_ZEROINIT
	址=全局锁定(内存);
	内存复制(址,内容,长);
	全局解锁(内存);
	如果(开剪切板(0))
	{
		清剪切板;
		写剪切板(1,内存);             // CF_TEXT = 1
		关剪切板;
	}
结束

程序 读回剪贴板
	整数 内存,址;
	缓冲(0)=0;
	如果(开剪切板(0))
	{
		内存=读剪切板(1);
		如果(内存<>0)
		{
			址=全局锁定(内存);
			放置(缓冲,址);
			全局解锁(内存);
		}
		关剪切板;
	}
结束
```

- 中文用 **`CF_TEXT=1`**（GBK），不要用 `13`（那是 `CF_UNICODETEXT`）。
- `全局分配` 后把 HGLOBAL 交给 `写剪切板`，**不要**自己 `释放内存`（所有权已转移）。

## 6. 自建 JSON：只「构造」不「解析」

极语言没有 JSON 库；本项目里**手写 JSON 解析过程会让编译器产出无法加载的 PE**（§9.1）。
所以只做构造，响应格式改由外部程序配合（§8）。

```ji
文本 报文[65536];
整数 报文位=0;

程序 报重置
	报文位=0; 报文(0)=0;
结束
程序 报字节(码)
	报文(报文位)=码; 报文位=报文位+1; 报文(报文位)=0;
结束
程序 报文字(内容)
	整数 n;
	n=文字长度(内容);
	内存复制(报文+报文位,内容,n);
	报文位=报文位+n;
	报文(报文位)=0;
结束
程序 报引号
	报字节(34);
结束

// 字符串转义：双引号 反斜杠 换行 回车 —— 用「标志变量」把嵌套压到一层
程序 报转义(内容)
	整数 i,c,转义,原样;
	i=0;
	循环
	{
		c=内容(i);
		如果(c=0){跳出}
		转义=0; 原样=1;
		如果(c=34){转义=1}
		如果(c=92){转义=1}
		如果(c=10){转义=1}
		如果(c=13){转义=1}
		如果(c=10){原样=0}
		如果(c=13){原样=0}
		如果(转义=1){报字节(92)}
		如果(c=10){报字节(110)}
		如果(c=13){报字节(114)}
		如果(原样=1){报字节(c)}
		i++;
	}
结束
```

- 字面量写法：`"He said ''hi''"` —— **`''` 编译出来就是一个双引号 `"`**（实测，
  见示例 30 输出）。极语言字符串**不支持 `\"`**。
- 组装示例：`报文字("{");报引号;报文字("cmd");报引号;报文字(":");...`

## 7. 启动外部进程（`创建进程`）

`lib.htm/msapi.htm` 的签名（**10 个参数，与 `CreateProcessA` 一一对应**）：

```
创建进程(名称, 命令, 进继, 线继, 全继, 标志, 环境, 目录, 启动, 进程)
         lpApplicationName, lpCommandLine, lpProcessAttributes, lpThreadAttributes,
         bInheritHandles, dwCreationFlags, lpEnvironment, lpCurrentDirectory,
         lpStartupInfo, lpProcessInformation
```

`启动信息类` / `进程信息类` **不能直接用**（编译器不认），要自己 `结构` 声明：

```ji
结构 启动结构{整数 大小,预留,桌面,标题,左,顶,宽,高,列,行,属性,标志,显示,备用,输入,输出,错误;}  // STARTUPINFOA 68 字节
结构 过程结构{整数 进程,线程,进程号,线程号;}                                                     // PROCESS_INFORMATION 16 字节

程序 启动引擎
	整数 成功;
	格式化(进程命令,"%s %s",解释器路径,脚本路径);   // ★ 用 格式化 拼串，别手工 memcpy
	启动项.大小=68;
	成功=创建进程(0,进程命令,0,0,0,$08000000,0,根目录,启动项,过程信息);  // CREATE_NO_WINDOW
	引擎句柄=过程信息.进程;      // ★ 句柄在 过程信息.进程，不是返回值
	// 结束时：终止进程(引擎句柄,0)
结束
```

- `lpCommandLine` 必须是**可写缓冲**（`文本`），CreateProcess 会就地修改它。
- 关掉子进程控制台窗口用 `$08000000`（`CREATE_NO_WINDOW`）。
- 拿不到可执行文件目录时：`模块名称(0,根目录,512)`（= `GetModuleFileNameA`，返回长度），
  再截断到最后一个 `\`——**`根目录(i+1)=0` 要保留反斜杠**，写 `根目录(i)=0` 会少一个分隔符。

## 8. Winsock 客户端与「定长前缀」协议

GUI.inc 已经 `引入 ws2_32.lib`，**GUI 程序里可直接用**网络函数。
（控制台程序要在 `模块文件=CMD.inc,dll.inc` 里带上 `dll.inc`。）

```ji
程序 连接探测(网址,端口号)
	文本 数据[400],地址[16];
	整数 启,网,连;
	启=网络启动($202,数据);       // WSAStartup
	网=分配(2,1,6);               // socket(AF_INET, SOCK_STREAM, IPPROTO_TCP)
	如果(网<0){返回(-1)}
	地址(0)%=2;                    // sin_family
	地址(2)%=反转(端口号);          // htons
	地址(4)&=转换地址(网址);        // inet_addr
	连=连网(网,地址,16);            // connect
	关闭(网);网络终止;
	返回(连)
结束
```

### ★ 在 GUI 程序里发 HTTP 会踩的坑（实测）

- `发送()` 一个由 `格式化()` 构造的 **HTTP 头缓冲**，在 GUI 程序里恒返回 `-1`；
  但 `发送()` 一个由 `本地转UTF8()` 产生的缓冲返回正常字节数。
  同代码在控制台程序里正常。→ **不要在 GUI 程序里拼 HTTP 头**。
- 结论：用**裸 TCP + 定长前缀**，一发一收，最稳：

```
请求 = 8 字节 ASCII 十进制长度 + UTF-8 载荷
响应 = 8 字节 ASCII 十进制长度 + UTF-8 载荷（随后关闭连接）
```

```ji
// 请求侧（全部用全局缓冲，避免把参数当缓冲用）
程序 发请求
	整数 码,文长;
	本地转UTF8(报文,报文位,请求暂存,65536);   // 先转 UTF-8
	文长=转换长度;
	格式化(头缓冲,"%08d",文长);               // ★ 长度前缀用 格式化，别手写取余循环
	内存复制(请求UTF8,头缓冲,8);
	内存复制(请求UTF8+8,请求暂存,文长);
	发送长=8+文长;
	码=原始发送(端口);                        // send(网,请求UTF8,发送长,0)
	// 响应：跳过前 8 字节，其余就是载荷
	UTF8转本地(响应体+8,显示,131072);
结束
```

`接收` 侧：`循环(总<上限){ n=接收(网,响应体+总,上限-总,0); 如果(n>0){总=总+n} 否则{跳出} }`
——**目标缓冲用全局**（`响应体+总`），不要用过程参数（§9.2）。

## 9. ★ 新增致命陷阱（本项目实测复现）

| # | 现象 | 最小复现 / 正确写法 |
|---|---|---|
| 9.1 | 编译 `BUILD_OK`，但 `CreateProcess` 报 **193（不是有效 Win32 程序）**；PE 头自洽、文件长度也对 | 特定源码形态（尤其是「过程里做 JSON 扫描 + 嵌套循环」）会产出 Windows 拒绝加载的镜像。把该过程删掉立刻恢复。**用 `scripts/build-check.ps1` 编译后校验产物能否加载**；真遇上就拆函数 / 改写法 |
| 9.2 | **`0xC0000005`** —— 在 `如果(...)` **条件里调用自定义过程** | `如果(取键文字(显示,"result",临时值,4096)>0){…}` 必崩。改成先赋值：`整数 长=取键文字(...); 如果(长>0){…}` |
| 9.3 | **`0xC0000005`** —— 在自定义过程里对**参数**做指针加减 | `内存复制(基底+n,尾部,len)`（基底/尾部都是参数）必崩；`发送(网,参数缓冲,长,0)` 也不可靠。改成：全局缓冲 + 偏移，拼串用 `格式化(基底,"%s%s",前缀,尾部)` |
| 9.4 | 运行期 **`0xC0000409`（栈缓冲溢出）** | 在**定时器回调**里连续走「网络请求 → 写库 → 刷列表」这类多层调用，数秒后崩。**把这段从定时器回调里挪到按钮事件**即完全稳定。本项目最终用「翻译」按钮而不是输入即译 |
| 9.5 | 轮询等待循环**不提前退出** | `循环(n<上限){延时;n++;长度=读文件;端口=转整数();如果(端口>0){n=9999}}` 这种写法在 GUI 程序里实测跑满全部次数（控制台里同样写法正常）。**改用「用到时再读」的惰性方式**，不要长时间阻塞消息循环 |
| 9.6 | 手写「整数取十进制数位」的循环结果错乱 | `余=值-(值/10)*10;缓冲(i)=48+余;值=值/10;` 在某个过程里首轮算出 `余=50`（本该 0），字节变成 `b`。**整除本身是对的**（`50/10=5`、`7/2=3` 实测），但别手写数位循环 → 用 `格式化(缓冲,"%08d",值)` |
| 9.7 | `文件写入(字面量,1,n,句柄)` 必崩 | 数据必须来自 `文本` 变量/缓冲。先 `放置(缓冲,"文字")` 再 `文件写入(缓冲,1,n,句柄)` |
| 9.8 | 过程里**局部声明写在语句之后** | 报「未定义的名称:xxx」或运行期崩。**每个 `程序` 开头先把所有局部声明列完** |
| 9.9 | `循环(1)` 只跑一次 | `循环(n)` = 重复 n 次；死循环写 `循环` 或 `循环{…跳出}` |

## 10. 构建产物校验（强烈建议纳入流程）

`sec.ps1` 只判断「有产物 + 无错误信息」，**判断不了 PE 能不能加载**。
本技能新增 `scripts/build-check.ps1`：编译后调用 `CreateProcess` 试启动，输出
`LOAD_OK` / `LOAD_FAIL(193)`，并能顺带把「GUI 程序运行 N 秒是否还活着」一起测掉。

```powershell
powershell -File <skill>\scripts\build-check.ps1 -Src app.txt
powershell -File <skill>\scripts\build-check.ps1 -Src app.txt -RunSeconds 5   # GUI 程序保活测试
```

## 11. 自动化测试技巧（无鼠标/键盘时）

1. **给 GUI 程序灌文字，必须用 `WM_CHAR` 模拟真实键入**：
   `PostMessageA(编辑框,0x0102,字符,0)` 逐字符发。
   **外部进程用 `SetWindowTextA` 灌进去的文字，本进程内 `~` 读不到**（实测：
   外部 `GetWindowTextA` 能看到、程序内读到空字符串），这是测试假象，会让人白查半天。
2. **点按钮用 `PostMessageA(hwnd, 0x0111, 按钮ID, 0)`**（`WM_COMMAND`），
   比 `SendMessageTimeout` 省心（后者在 C# 互操作里 signature 写错会一直返回 0）。
3. **`SendMessageTimeoutA` 读控件文字要用 ANSI 版 + `byte[]`**，再用 GBK 解码：
   `SendMessageTimeoutA(h,0x000D,size,buf,...)`；用 `StringBuilder`/`WM_GETTEXTW`
   去读 ANSI 窗口会读出乱码，误判成「程序写错了」。
4. **`sec.ps1 -Run` 抓不到 GUI 的 stdout**，用截图或 `GetWindowText` 断言。
